# Portfolio

A simple stock portfolio system

## Assumptions

- The opening price of a stock is not relevant to the portfolio.
  - This can be extended with a `PortfolioStock` class that stores such information in order to display a transaction history to the user.
- The ID assigned to a stock is unique. If two stocks with the same ID are added to the portfolio, their shares are summed.
- Shares are whole units, meaning fractional shares cannot be purchased.
  - This can be extended by using `BigDecimal` or rounding to a fixed number of decimal places.
- Prices use the smallest possible unit to remain as integers and avoid precision issues: for example, CLP pesos or USD cents.
- Percentages are integer values
  - This can be extended by using `BigDecimal` or rounding to a fixed number of decimal places.
- During rebalancing, the portfolio value cannot increase: the rebalance cannot "inject money" into the system, it can only use the money generated by the sales within the same process.
- The rebalance only indicates what should be done, it does not execute the actions.
  - The problem literally states: "Provide a portfolio rebalance method **to know** which Stocks should be sold and which ones should be bought".
- Only shares exist in the portfolio, there is no uninvested cash.
  - This can be extended by adding a cash variable to the system and treating it as a source of funds for the rebalance.

## Logic

The algorithm (`calculate_rebalance`) is divided into three phases: freeze, rebalance and value verification

### Freeze

Prices and values in the portfolio are frozen to prevent changes during the algorithm.

### Rebalance

The shares to buy and sell are calculated:

- All stocks that are not part of the target allocation are sold.
- For the remaining stocks, the difference between the target number of shares and the current number of shares is calculated. The target is computed by applying the target percentage to the total portfolio value, divided by the stock's price (the goal is to balance value, not the number of shares). For example:
  - A portfolio has 10 shares of A and 20 shares of B. The price of A is $30 and B is $50.
  - The target allocation is 30% A and 70% B.
  - The portfolio value is 10*$30 + 20*$50 = $1300.
  - The target for A is ($1300 * 30%) / $30 = 13 => the difference is 13 - 10 = 3 (buy).
  - The target for B is ($1300 * 70%) / $50 = 18.2 ~18 => the difference is 18 - 20 = -2 (sell).

### Value verification

The total value to buy must be less than or equal to the total value sold.

- This can be violated when rounding shares to the nearest integer. In that case, stocks are iterated in insertion order and each stock's buy amount is reduced by 1 until the condition is met
- This can be extended by sorting stocks by price before starting the reduction, or by using an algorithm that minimizes the number of reductions.

## Local deployment

Requires Ruby 3.2.2.

```bash
# Install dependencies
bundle install

# Run tests
bundle exec rspec .

# Run Sorbet type checker
bundle exec srb tc

# Run linter
bundle exec rubocop --force-exclusion
```
